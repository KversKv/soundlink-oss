# 05 · 配对与安全（Pairing & Security）

## 1. 用户流程

```text
1. 用户打开桌面端 → 进入“接收模式”
2. 桌面端显示 6~8 位配对码
3. 手机 App 通过 mDNS 搜索到桌面设备
4. 用户在手机 App 输入配对码
5. 双方基于配对码完成密钥协商
6. 保存设备信任关系（公钥）
7. 用户开启手机屏幕/媒体广播
8. 音频开始传输
9. 下次连接使用已保存信任自动连接
```

## 2. 配对码设计

| 项目 | 推荐 |
|---|---|
| 长度 | 6 位起步，推荐 8 位 |
| 有效期 | 120 秒 |
| 尝试次数 | 3~5 次后失效 |
| 展示 | 桌面端 UI + 可选二维码 |
| 下次连接 | 已保存信任自动连接 |

## 3. 安全模型

> **不要把配对码直接当传输密码。** 配对码只用于一次性引导密钥协商。

```text
配对码
  → PAKE 密钥协商 (SPAKE2 / SRP)
  → 生成会话密钥
  → 交换并保存设备身份公钥 (Ed25519)
  → 后续连接用设备身份认证 + X25519 会话密钥
  → 音频包用 ChaCha20-Poly1305 加密
```

## 4. 算法选型

| 用途 | 推荐 | 第一版可简化 |
|---|---|---|
| 配对密钥协商 | SPAKE2 / SRP | 配对码 + X25519 + HMAC 校验 |
| 设备身份 | Ed25519 | 同 |
| 会话密钥交换 | X25519 | 同 |
| 音频包加密 | ChaCha20-Poly1305 | 同 |
| 摘要 | SHA-256 | 同 |

> 第一版资源有限时可用 `配对码 + X25519 + HMAC`；正式商业版升级到 PAKE（SPAKE2/SRP），避免配对码离线爆破风险。

## 5. 信任存储

| 端 | 存储 |
|---|---|
| iOS | Keychain（App Group 共享给 Extension） |
| Android | Android Keystore / EncryptedSharedPreferences |
| 桌面 | 本地安全存储（OS keyring 或加密的本地文件/SQLite） |

## 6. 威胁与应对（局域网）

| 威胁 | 应对 |
|---|---|
| 同网段窃听 | AEAD 加密音频与控制面 |
| 中间人配对 | PAKE / 配对码短时效 + 尝试次数限制 |
| 重放攻击 | sequence + timestamp + nonce 校验 |
| 伪装设备 | 设备身份公钥固定与信任校验 |
