# 06 · 延迟与体验（Latency & Experience）

## 1. 延迟拆解

### iOS → 桌面

| 环节 | 延迟 |
|---|---:|
| ReplayKit 捕获 | 80–200 ms |
| 音频格式转换 | 2–10 ms |
| Opus 编码 | 5–15 ms |
| 局域网传输 | 1–10 ms |
| Jitter Buffer | 40–100 ms |
| Opus 解码 | 2–5 ms |
| 桌面音频输出 | 10–30 ms |
| **总计** | **~140–370 ms** |

### Android → 桌面
- 采集环节（AudioPlaybackCapture）通常略低于 ReplayKit，总计约 **120–320 ms**，因机型/系统差异大。

### 桌面 → 桌面

| 链路 | 延迟 |
|---|---:|
| Windows → Windows | 30–100 ms |
| macOS → Windows | 40–120 ms |
| macOS → macOS | 40–120 ms |

## 2. 场景体验判断

| 场景 | 体验 |
|---|---|
| 听音乐 | 好 |
| 看电影 | 基本可用，可能轻微音画不同步 |
| 长视频（B 站等） | 可用性较好 |
| 短视频（抖音等） | 可能感知音画不同步 |
| 游戏 | 不推荐 |
| 直播连麦 | 不推荐 |

## 3. 输出耳机附加延迟

| 耳机类型 | 额外延迟 |
|---|---:|
| 有线耳机 | ~0 ms |
| USB 耳机 | 很低 |
| 2.4G 游戏耳机 | 10–40 ms |
| 低延迟蓝牙耳机 | 40–120 ms |
| 普通蓝牙耳机 | 120–250 ms |

> 产品建议：为更好的音画同步，电脑端使用**有线 / USB / 2.4G 低延迟耳机**。

## 4. 结论

- **适合**：听音乐、看电影、长视频、桌面到桌面流转。
- **不主打**：短视频、游戏、连麦。
- iOS 端延迟受 ReplayKit 限制，无法做到极低。

## 5. 优化方向（后续）

- 自适应 Jitter Buffer（按抖动/丢包动态调整）。
- Opus 帧长降到 5 ms（权衡包数量与 CPU）。
- 码率自适应 + PLC 丢包补偿。
- 桌面输出 buffer 调优、独占/低延迟模式。
- 精确延迟估算与 UI 展示，引导用户选择合适模式与耳机。
