### 2.1 两条被推翻的早期结论（留档避免反复）

| 早期结论 | 为何推翻 |
|---|---|
| ~~全部 MIT，Pro 代码同在公开仓库，靠许可证开关控制~~ | 用户明确要求「不希望直接编译可以获得完全版本」。公开 Pro 代码等于把付费变成纯自愿捐赠，与「获取利润」的目标不符 |
| ~~Pro = EQ / 多接收端广播 / 诊断报表 / 主题包等额外功能~~ | **偏离产品核心**。SoundLink 的价值就是「音频流转」本身；用附加功能凑收费点会让 Pro 显得可有可无。Pro 应当是**同一件事做得更省心** |

### 2.2 划分总原则（收窄后）

| # | 原则 | 说明 |
|---|---|---|
| **P1 · 流转能力本身永久免费** | 手动完成「配对 → 开始接收/发送 → 出声」的完整链路永不收费。音质、延迟、码率、Jitter 档位、加密全部不设限 |
| **P2 · 安全永不收费** | 加密、密钥保护、MITM 防护、配对锁定不进 Pro |
| **P3 · Pro 只卖「少点几下、不用管它」** | Pro = **自动化 + 记忆 + 免打开窗口**。免费版每次能做到的事，Pro 版不需要你每次都做 |
| **P4 · 免费版必须是完整可用产品** | 不做时长/次数/音质限制，不插广告，不弹遮罩。用户可以永久只用免费版，不感觉残废 |
| **P5 · 不做「额外功能」凑数** | 与音频流转主链路无关的功能（EQ、录制、图表）**不作为首发 Pro 卖点**，见 §6 |

> 一句话概括 Pro 的价值主张：**「插上耳机就有声音，不用打开 SoundLink。」**

## 3. 免费版能力（MIT，主仓库可完整编译）

- 完整的手机 → 电脑、电脑 → 电脑音频流转
- Opus 全码率档位（64k–192k）、全 Jitter 档位（含 auto 自适应）、48kHz/Stereo 基线
- ChaCha20-Poly1305 加密、X25519/Ed25519 配对、keyring 密钥存储、公钥不一致阻断
- mDNS 发现、8 位配对码、配对锁定
- 输出设备选择、音量控制、音频参数调整
- **记忆 1 个已配对设备**（下次可免配对码直连该设备）
- 手动开始/停止接收与发送
- 最小化到托盘（关窗口不退出）
- 状态面板：实时丢包 / 缓冲 / 抖动 / PLC 数值
- 日志查看与导出、首次引导
- 全部移动端功能
- 全部免费核心源代码（MIT）

## 4. Pro 功能清单（￥9.99 买断）

**全部围绕「让流转自动发生」。** 编号对应 [`01-engineering-plan.md`](./01-engineering-plan.md) 实现任务。

| # | 功能 | 免费版对应体验 | Pro 体验 |
|---|---|---|---|
| **PRO-1** | **开机自启 + 启动即进入收/发模式** | 每次开机手动打开 SoundLink，点「开始接收」 | 开机后无感知地进入接收（或发送）状态，窗口不弹出 |
| **PRO-2** | **记忆并自动重连上次设备** | 每次手动选设备、点连接；断线后手动重连 | 启动/断线后自动重连上次设备，指数退避静默重试 |
| **PRO-3** | **多设备记忆（免费版上限 1 个）** | 只能记住 1 台对端；换设备要重新走配对码 | 记住最多 **8 台**，随时切换免配对 |
| **PRO-4** | **多套配置一键切换** | 单套配置；换用途要逐项改设备/Jitter/音量 | 保存「客厅音箱 / 桌面耳机 / 录音声卡」等档位，一键切换 |
| **PRO-5** | **全局快捷键与托盘直控** | 需打开主窗口才能操作 | 快捷键/托盘菜单直接开始停止、切换设备、静音，不打开窗口 |

### 4.1 组合价值（这才是 9.99 的理由）

单看每一项都不大，但组合起来改变的是**使用方式**：

> 免费版：开机 → 找到 SoundLink → 打开 → 选设备 → 点开始 → 出声（约 5 步，每天数次）
> Pro 版：开机 → 出声（0 步）

这正是用户所说「对用户感知更明显」的体验优化，也是同类工具（AudioRelay 等）付费档的典型内容。

### 4.2 三项自动化开关已实装（本次为「归属调整」）

`auto_start` / `auto_receive_on_start` / `auto_send_on_start` 已在 [`config/mod.rs`](../../../desktop/src-tauri/src/config/mod.rs) 与 [`commands/mod.rs`](../../../desktop/src-tauri/src/commands/mod.rs#L930-L1037)、[`App.tsx`](../../../desktop/ui/src/App.tsx#L316-L351) 落地。本次改造是**把这三个开关移入 Pro 门控**，而非从零开发。

因 `0.1.0-beta.1` 无真实用户（§2 决策），此调整**不构成对既有用户的功能回收**。首个含 Pro 的版本（`v0.3.0`）发布说明中仍需注明该归属，避免测试期使用者困惑。

### 4.3 全局快捷键现状与调整

现有全局快捷键（`Ctrl+Shift+P` 切角色 / `Ctrl+Shift+S` 显主窗口）在 [`main.rs`](../../../desktop/src-tauri/src/main.rs#L50-L77) 无条件注册。

调整方式：
- **`Ctrl+Shift+S`（显示主窗口）保持免费** —— 这是「找回被最小化的窗口」的基本可用性，收费不合理。
- **`Ctrl+Shift+P` 及新增的开始/停止/切设备/静音快捷键归 Pro**。
- 托盘「最小化/退出」保持免费；托盘菜单里的**收发直控项**归 Pro。

## 6. 明确排除的收费候选（不做，避免方案再次发散）

| 被排除 | 理由 |
|---|---|
| EQ / 响度归一 / 音频增强链 | 与「流转」无关的附加功能，偏离核心（P5）；工程量大、收益不确定 |
| 音频录制、定时器 | 同上；且易被理解为「另一个软件的功能」 |
| 诊断图表与报表导出 | 免费版已给实时数值，做成付费图表价值感低 |
| 主题包 / 外观自定义 | 与核心无关，且外观收费廉价感强 |
| 多接收端广播（1→N） | 这是**新能力**而非体验优化，工程量最大；留作 v0.5+ 独立评估，不进首发 Pro |
| 更低延迟 / 更高码率档位 | 违反 P1/P4——故意让免费版听感更差 |
| macOS / Linux / iOS 支持 | 跨平台是免费路线承诺，收费即背信 |
| UI 英文 i18n | 属免费任务（P2-I3） |
| 技术支持优先级 | 会让 Issue 区分二等公民 |
| 使用时长 / 连接次数限制 | 典型 crippleware，违反 P4 |

> 上表条目若未来要启用，必须先在本节记录理由并获用户批准。

## 7. 开源模型：主仓库 MIT + 私有 Pro crate

### 7.1 结构

```
公开仓库 SoundLink（MIT）
├── desktop/pro-api/              crate soundlink-pro-api：Pro 能力的 trait 定义
├── desktop/pro/                  crate soundlink-pro：免费实现（记 1 台、不自动启动）
├── desktop/src-tauri/            免费核心，完整可编译可用；恒定 path 依赖上面两个 crate
└── ...

私有仓库 soundlink-pro（不公开，crate 名与公开侧同名）
└── src/                          PRO-1~PRO-5 的真实实现
```

- 公开仓库 `cargo build` → **完整可用的免费版**，无残缺、无死代码、无「此处省略」。
- 官方构建在有私有仓库访问权的 CI 中，先把私有实现**检出覆盖 `desktop/pro/`** 再构建；构建命令与免费版完全相同。
- 不使用 `--features pro` 式可选私有依赖：Cargo 会解析可选依赖，会导致社区默认构建失败（**已实测确认**，见 `02` §11 V-1）。

> 具体的编译与使用操作见 [`02-multi-repo-guide.md`](./02-multi-repo-guide.md)。

### 7.2 为什么选这个形态

| 方案 | 结论 |
|---|---|
| 全部 MIT 靠许可证开关 | ❌ 已推翻（§2.1） |
| **私有 Pro crate** | ✅ 采用。免费核心依然是**诚实完整**的开源软件；Pro 逻辑不公开，编译不出来 |
| 公开仓库仅留空接口壳 | ❌ 免费版代码会出现明显空洞，社区会质疑「这是开源诱饵」 |
| 预编译二进制模块（dll/so） | ❌ 平台加载复杂度 + 安全审计争议 |

### 7.3 诚实沟通口径（必须写进 README 与官网）

1. **核心音频流转功能永久免费、完整开源（MIT），可自行编译得到与官方一致的免费版。**
2. Pro 是**自动化与便捷性增强**，其实现代码不开源；这是项目维持开发的方式。
3. Pro 授权**完全离线校验，不联网、不上传任何信息**。
4. 一次购买￥9.99，永久有效，含后续 Pro 新功能；7 日内可退。

> 不要说「开源软件」而暗示全部开源。准确表述：**「核心开源 + Pro 增强闭源」的 open-core 模型**。含糊表述带来的信任损失远大于收益。

## 8. 定价与渠道

### 8.1 定价

| 项 | 值 |
|---|---|
| 价格 | **￥9.99**（一次性） |
| 授权范围 | 个人非商业使用，同一自然人最多 **3 台设备** |
| 有效期 | 永久，含所有后续版本（不做年度升级费） |
| 试用 | **不设限时试用**。Pro 开关在 UI 中可见、带说明、点击引导购买 |
| 退款 | 7 日内无理由 |
| 贡献者 | 合并过 PR 的贡献者免费发 key |

**为什么 9.99 买断**：目标用户是个人耳机用户；竞品 AudioRelay 为约 $1/月 freemium，一次 9.99 ≈ 竞品 1.5 个月，「不到一杯奶茶，永久」易传播。买断制也无需维护续费/到期降级逻辑，与离线许可证天然契合。

### 8.2 渠道与发货

| 渠道 | 定位 | 发货 |
|---|---|---|
| **爱发电** | 主渠道（GitHub / V2EX / 少数派 来源） | 设「9.99 元 · SoundLink Pro 授权」档位；用户下单时在备注提供设备指纹 → 回发 key |
| **淘宝小店** | 搜索型用户，信任成本低 | 旺旺索取指纹 → 回发 key |

**流程（方案 A · 指纹绑定，默认）**
1. 用户在「设置 → Pro」复制**设备指纹**（10 位短码，单向哈希，不含隐私信息）。
2. 下单时提交指纹。
3. 卖方用私钥签发含该指纹的 license key。
4. 用户粘贴 key → 本地公钥验签 + 指纹比对 → 激活。

**降级选项（方案 B · 订单号绑定）**：需批量预发货时使用，只验签名不比对硬件，靠 key 内嵌买家标识形成社交约束。两者共用同一验签代码路径。

## 9. 收入预期与止损判据

| 情景 | 假设 | 月收入 |
|---|---|---|
| 悲观 | 月活 300，付费率 1% | ￥30 |
| 中性 | 月活 2000，付费率 3% | ￥600 |
| 乐观 | 月活 10000（iOS + 曝光），付费率 4% | ￥4000 |

> 因 Pro 闭源且功能是高频刚需（开机即用），付费率预期高于「全 MIT 可自编译」形态（后者通常 0.3–2%）。但**收入规模仍主要由装机量决定**。

**战略结论：优先做装机量，而不是转化率。** 免费版越强、用的人越多，Pro 绝对收入越高。任何削弱免费版以逼转化的动作长期都是负收益。

### 止损/复盘（v0.3.0 后 3 个月）

- 收入 < ￥200/月：不加码 Pro，把精力投回免费核心（跨平台、iOS）。
- 收入 > ￥1000/月：评估 §6 中被排除的候选与国际渠道。
- 出现 key 泄露传播：只在下一版把该 key 加入本地吊销名单，**不升级技术对抗**。

## 10. 风险清单

| 风险 | 影响 | 缓解 |
|---|---|---|
| **社区质疑 open-core 不够开源** | 口碑受损 | §7.3 口径必须准确、前置、不含糊；免费核心保持完整可用、无残缺代码 |
| **「开机自启这种基础功能也收费？」** | 差评 | 文案强调：免费版手动一键即可完成同样的事；Pro 卖的是「不用每次做」；对照表公开透明 |
| **免费版 1 台设备上限被认为过苛** | 转化率↑但口碑↓ | 1 台足以覆盖「一部手机 + 一台电脑」的主场景；若反馈集中，可放宽到 2 台（保留调整余地） |
| **私有仓库丢失/CI token 泄露** | Pro 源码外泄 | 私有仓库定期本地备份；CI 用最小权限 deploy key；泄露即接受既成事实，不做法律对抗 |
| **key 泄露传播** | 收入受损 | 指纹绑定 + 3 台上限 + 吊销名单；不引入联网校验以维持零遥测承诺 |
| **付费逻辑 Bug 锁住已付费用户** | 最严重信任事故 | 校验失败**降级为免费版而非阻止启动**；提供重新导入 key 入口；验签必须单测覆盖 |
| **代码签名缺失导致付费用户遇 SmartScreen** | 付费体验割裂 | 有收入后**优先购买代码签名证书**（对应 OSL-K5） |
| **淘宝/爱发电类目合规** | 店铺被处理 | 描述明确为「软件授权码」，附开源与授权说明 |
